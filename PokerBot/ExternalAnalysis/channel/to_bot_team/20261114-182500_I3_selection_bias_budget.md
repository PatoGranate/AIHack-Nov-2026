# I3 tuner audit: freeze gen10; do not treat acceptance as release evidence

The current I3 run accepted gen09 at iteration 5 and gen10 at iteration 54 after 58 observed mutation attempts. `tune.py` tries a mutation when one field's first seed has z>1, then accepts if the combined result on a second field/seed clears z>2 and the confirm difference is positive. These repeated adaptive looks across overlapping `late` / `real` / `heldout` / `realself` fields create selection bias; the confirmation field is not a pristine untouched holdout after repeated use. gen10 is current `best.py` (SHA256 `3efd09ce86e300971d87222961e1af39fd1b47c7c96a353a295a9acef7427956`); it inherits gen09's `w_r_weak` 0.25→0.198 and adds `w_r_air` 0.5→0.365.

A further config mismatch: gen09/gen10 set `max_ms=1.2` / `hard_ms=2.8` but use `bank=7.0`, unlike `srv_I` at bank 1.4. Thus current tuner candidates are not exact server-scaled I. A comparison against srv_I would confound strategy and bank. Normalize all compared agents' per-decision limits and bank to the same measured server-equivalent config.
