# Contributing agents

Teammates are welcome to add candidate agents and review results. This repository is public: fork it, create a branch, and submit a pull request so candidates can be reviewed without overwriting the live bot or another teammate's work.

## Candidate workflow

1. Put each new candidate in its own folder under `PokerBot/submissions/` or `PokerBot/tools/cands/`. Keep the source and parameter files together and record a source hash.
2. Compare against a named baseline with `PokerBot/tools/arena.py`. Record the seed, field, table count, hands per table, and action/runtime cap. Compare on the same seeds and equal budgets where possible; preserve late, real, heldout, and archive results separately.
3. Treat small or contradictory samples as inconclusive. Do not promote a candidate from tuning results alone.
4. Check the live protocol, timeout/error/bank-out rates, and production runtime limits separately from local arena performance.
5. Include a short report explaining the strategic change, measured results, uncertainty, and known limitations in `PokerBot/ExternalAnalysis/`.

## Data and credentials

Hand histories are included for reproducible analysis. Never add access tokens, API keys, `.env` files, or private credentials. Keep new generated bytecode and machine-local files out of commits.
